# Облачная среда Upscale

Рабочая папка: `/workspace/upscale_bot`. Используйте существующий checkout:
каждая задача уже изолирована. Дополнительный Git worktree не нужен.

## Проверено в текущей машине

Python 3.12.14, Linux Debian 13, Chromium `/usr/bin/chromium`.
Окружение Python: `/workspace/.venvs/upscale_bot`.
Установлен закреплённый `playwright==1.62.0`. Исходные зависимости, тесты,
стратегия и код архива сохранены без изменений.

Обязательные проверки разработки прошли: установка зависимостей, `pip check`,
все существующие 14 тестов, запуск Chromium и чтение свечей пяти пар.
Получено по 299 закрытых свечей на пару (всего 1495).
Для готовности уведомлений дополнительно нужна рабочая привязка Telegram.
Проверки исполнения сделок неприменимы: такого компонента в коде нет.

```bash
cd /workspace/upscale_bot
bash scripts/cloud_setup.sh
/workspace/.venvs/upscale_bot/bin/python scripts/cloud_run.py status
/workspace/.venvs/upscale_bot/bin/python scripts/cloud_run.py feed
```

`feed` читает только публичные котировки и не использует Telegram. Требуются
пять пар, минимум пять закрытых свечей на пару; исключения означают неуспех.
`status` до первого запуска возвращает `{}` — это отсутствие сохранённого
состояния, а не свидетельство работающего наблюдателя.

## Сеть и доступ Chromium

Нужны HTTPS-домены `app.upscale.trade` и `api.telegram.org`, кроме уже доступных
источников пакетов `pypi.org` и `files.pythonhosted.org`.
Изначально оба прикладных домена были заблокированы прокси (CONNECT 403).
Домены были добавлены в черновик; затем настройки пользователя изменились
на неограниченный доступ. Этот выбор сохранён. Текущие запросы к Upscale
и Telegram проходят; готовность сети проверялась реальными запросами.

Сохраняйте платформенные `HTTPS_PROXY`/`HTTP_PROXY` и доверенные сертификаты;
не отключайте TLS-проверку. Отдельный браузер Playwright скачивать не требуется:
проект использует установленный системный Chromium.

В файловой песочнице Chromium получает `ERR_CERT_AUTHORITY_INVALID`: NSS пытается
открыть `/home/agent/.pki/nssdb/cert9.db` для записи и получает `EROFS`.
Платформенный CA уже присутствует в NSS под именем `OpenAI-nebula-dns`.
Поэтому добавлять дубликат сертификата или менять его проверку не нужно.
Команда `feed` успешно проверена через `exec_command` с
`sandbox_permissions="require_escalated"`, разрешающим браузеру доступ к NSS.
Такой же доступ нужен процессу наблюдателя. Обычный локальный DOM/JS-тест
Chromium прошёл и без расширения файлового доступа.

## Telegram и запуск

Переменная `TELEGRAM_BOT_TOKEN` в машине присутствует. Проверка `getMe` прошла,
но она относится к другому боту, а не к прежнему `@aiagentupscale_bot`.
Её значение не выводилось. Существующая настройка сохранена.
Для Upscale добавлено отдельное требование `UPSCALE_TELEGRAM_BOT_TOKEN`;
внесите значение для `@aiagentupscale_bot` безопасно через настройки среды.
Launcher предпочитает эту переменную, затем пробует прежнюю и проверяет имя
бота. Неподходящая конфигурация не записывается; сообщений проверка не отправляет.

Приватное состояние запуска находится в `/workspace/.state/upscale_bot`, вне
checkout. При необходимости задайте отдельную папку через `UPSCALE_STATE_DIR`.
Облачный launcher направляет туда исходные модули, не меняя их код и `HOME`.
Он не подменяет конфигурацию и результаты из `reference/` рабочим состоянием.

После заполнения `UPSCALE_TELEGRAM_BOT_TOKEN`:

```bash
cd /workspace/upscale_bot
/workspace/.venvs/upscale_bot/bin/python scripts/cloud_run.py configure
/workspace/.venvs/upscale_bot/bin/python scripts/cloud_run.py binding-link
```

`configure` выполняет только Telegram `getMe`, проверяет имя бота и сохраняет
локальную конфигурацию с правами 0600. Существующая конфигурация сохраняется.
`binding-link` выводит локальную персональную ссылку; откройте её и нажмите Start.
Токен, ссылку привязки и файлы состояния не помещайте в Git или переписку.
Прежняя привязка и курсор Telegram не входят в архив.

Перед запуском убедитесь, что старый экземпляр этого бота остановлен: два
наблюдателя не должны одновременно читать Telegram getUpdates.
Полный запуск читает команды и может отправлять уведомления в привязанный чат;
в рамках переноса сообщений и настройки среды он не выполнялся.

```bash
/workspace/.venvs/upscale_bot/bin/python scripts/cloud_run.py once
/workspace/.venvs/upscale_bot/bin/python scripts/cloud_run.py supervisor
```

`once` читает рынки и записывает состояние, не рассылая входные сигналы.
Перед ним нужна конфигурация Telegram. После успешной проверки `supervisor`
запускает наблюдатель с перезапуском при авариях. Проверьте `status`: phase
`observing`, пять рынков, свежий `last_scan_at`, `execution_enabled=false`.
Для проверки именно уведомлений нужны явный запрос отправки и подтверждение
Telegram; такой тест при переносе не проводился.

Процессы не переживают остановку среды. Для непрерывной работы нужен
постоянный хостинг; его настройка в эту среду не входит.

## Сохранение работы

Все файлы находятся в существующем checkout. У удалённого репозитория при
проверке не было refs или коммитов; локальная ветка `work` ещё без первого
коммита. Публикация GitHub не выполнялась.

Пять скриншотов стратегии включены в набор файлов Git. Одиннадцать
диагностических снимков сохранены под `runtime/context-2026-10-21/images/`,
который игнорируется исходным `.gitignore`; публикация Git не перенесёт их.
Снимок облачной среды должен сохранять их вместе с установленными зависимостями.
Конфигурация установки и запуска сохраняется отдельно в настройках среды;
для применения к будущим задачам пользователь публикует среду.

Подробные результаты текущей проверки сохранены в
`context/2026-10-21/environment-validation.json`. Проверка уведомлений, полный
запуск supervisor и восстановление в новой задаче ещё не выполнялись.
