# Автоматический поиск предыдущих запусков

Скрипт принимает Solana CA, сам выбирает ветки расследования и сохраняет результат, доказательства, журнал действий и готовый сценарий повторного запуска. Нужен Node.js 20+, для `--use-env-proxy` — Node 24. Зависимостей npm нет. Анализ только читает блокчейн.

```bash
cd devlens
node investigate-cli.mjs CURRENT_CA --creator=DEV_WALLET
```

`--creator` необязателен: сначала проверяется реестр и поддерживаемые транзакции создания. Если источник не позволяет установить оператора запуска, скрипт сообщает об этом, а не объявляет плательщика комиссии разработчиком.

Для своего RPC создайте **локальный, не публикуемый** файл `rpc.local.json`:

```json
{"url":"https://YOUR_SOLANA_MAINNET_RPC"}
```

```bash
node investigate-cli.mjs CURRENT_CA --rpc-file=rpc.local.json --deep
```

Можно использовать переменную `DEVLENS_RPC_URL`. В managed cloud запускайте `node --use-env-proxy ...`, сохраняя proxy и CA окружения. Не передавайте секретный URL в аргументах командной строки. Ключи не добавляются в отчёт, сценарий или архив поставки.

## Как выбирается ветка

1. **Тот же оператор:** найти и проверить реальные более ранние создания его адресом. Для Pump проверяются события программы, для Raydium LaunchLab и Meteora DBC — поддерживаемые инструкции и инициализация именно этого mint. Поля `user`, `creator`, оператор пула и payer не смешиваются.
2. **Поменялся кошелёк:** исследовать подписанные пополнения до запуска, обратные переводы, синхронный сбор средств, передачу полномочий программы. Сам по себе общий фандер остаётся гипотезой. На массовых узлах ветка останавливается.
3. **Повторилась группа:** прочитать реальные приобретения mint в блоке запуска, сравнить с памятью порядок, адреса и совместные подписи. Если память не помогла — ограниченно искать пересечения старых приобретений группы и отдельно проверять создание и раннюю группу каждого кандидата. Торгуемый токен не становится «предыдущим запуском» от одного факта покупки.
4. **Недостаточно данных:** вернуть неполное покрытие, неизвестный запуск или отсутствие поддержанного кандидата в проверенной области. Пустой результат не доказывает, что предыдущего запуска нет.

Поддерживаются Pump CreateEvent и event CPI при усечённых логах, обычный SPL и Token-2022 в поддерживаемых LaunchLab/DBC инициализаторах. Другие программы и неизвестные версии инструкций не объявляются проверенными автоматически. Это расширяемый набор адаптеров, а не поддержка всех существующих площадок.

Из доказательств предыдущего запуска исключаются:

- привязанные, расчётные и quote-активы;
- обычные покупки/продажи, read-only упоминания адресов;
- микропереводы, возвраты rent и обёртка SOL на свой token account;
- один случайный ранний покупатель, общая биржа и сервисные подписи оплаты.

Дополнительные исключения: `--exclude=CA1,CA2`. Базовые известные расчётные активы задаются в `QUOTE_ASSETS`, адресные гипотезы предыдущих запусков в код не зашиваются.

Баллы используются для сортировки доказательств. Они не являются вероятностью и не устанавливают общего человека-владельца.

## ИИ сначала выбирает проверки, алгоритм проверяет факты

Проверенные вручную цепочки расследования перенесены в типизированные действия. Необязательный планировщик OpenAI выбирает следующие действия из уже наблюдаемых адресов и кандидатов; он не может придумать CA, выполнять код, менять пороги, отправлять транзакции или открывать произвольные URL.

Для ИИ задайте `DEVLENS_OPENAI_API_KEY` (или `OPENAI_API_KEY`) в локальном окружении и запустите с `--ai`. Модель задаётся `DEVLENS_OPENAI_MODEL`, по умолчанию `gpt-4.1-mini`. Скрипт отправляет компактные факты и варианты действий в OpenAI Responses API с `store:false`. Секрет RPC не отправляется. Тексты проектов считаются недоверенными данными.

Без API-ключа работает автоматический алгоритм; результат содержит `ai.state: "unconfigured"`. Флаг `--ai` требует ключ и не выдаёт обычный алгоритм за использование модели. Сбой модели оставляет алгоритмический поиск доступным. Пропущенные факты не заполняются догадками.

## Выходные файлы и повторное выполнение

По умолчанию файлы сохраняются в `research/investigations/`:

- `CA.json` — результат с источниками, кандидатами и покрытием;
- `CA.md` — читаемый отчёт;
- `CA.recipe.json` — параметры и фактически выполненные шаги;
- `CA.run.mjs` — сгенерированный сценарий повторного запуска.

```bash
node research/investigations/CA.run.mjs --rpc-file=rpc.local.json
# Или напрямую:
node investigate-cli.mjs --recipe=research/investigations/CA.recipe.json
```

Повторный запуск вновь выполняет алгоритм с параметрами сценария; он не воспроизводит старые результаты как свежие. При новых данных ветка может отличаться. `--out=PATH.json` задаёт место сохранения. Кэш неизменяемых транзакций и блоков ускоряет повторные проверки; история кошельков имеет TTL 60 секунд, реестр — 5 минут. `--fresh` игнорирует кэш. Ключи не сохраняются в кэше; там находятся только публичные ответы.

База остаётся локальной. Экспорт из браузера DevLens можно передать через `--memory=BACKUP.json`. Сам скрипт не записывает данные напрямую в IndexedDB другого браузера.

## Самокалибровка на известных примерах

```bash
npm run calibrate
node investigate-cli.mjs CURRENT_CA --config=research/calibration/selected-config.json
npm test
```

Калибровка перебирает 12 сочетаний порогов. Сначала алгоритм самостоятельно исследует архивные ответы; ожидаемые CA используются только после поиска для оценки. Сохранённый ответ для текущего токена и подтверждённые пользователем пары не подаются в алгоритм как готовый результат.

Примеры в `calibration/examples.json`:

| Случай | Проверяемое поведение |
| --- | --- |
| GLASS → SH | Повтор ранней группы на LaunchLab / Meteora DBC; связь группы подтверждена пользователем |
| BOUNCER → PRIME | Создания связанных кошельков, частное финансирование, полномочия программы; это кандидат, личность владельца не установлена |
| VICE | GTA VI исключается как привязанный актив; настоящий предыдущий запуск остаётся неизвестным |

Три примера — проверка поведения, **не оценка точности на новых токенах**. Настройки выбираются по двум калибровочным примерам; отрицательный контроль выводится отдельно и не участвует в выборе. Неизвестные результаты не размечаются как ошибки или подтверждения. Новые проверенные случаи можно добавлять в manifest и архивы, сохраняя различие подтверждения, гипотезы и неизвестного исхода.

Архивы `test/fixtures/investigation/*.json.gz` содержат публичные mainnet-ответы. В блоках сохранены исходные позиции и все балансы исследуемых mint; ненужные инструкции посторонних транзакций опущены. Недостающий запрос остаётся неизвестным, а не успешным пустым ответом. Проверка архивного режима не делает сетевых запросов:

```bash
node investigate-cli.mjs DwdiS94nXvBzQJSYNSRjdAUMK9BJ7sxeXMXfQxVM95Vg --archive=test/fixtures/investigation/glass.json.gz
```

По умолчанию ограничены время, количество адресов, транзакций и страниц истории. `--deep` расширяет эти пределы. HTTP 429 останавливает поиск без ротации провайдеров для обхода лимита. Новая независимая проверка через live RPC необходима для оценки работы на незнакомых данных. Обновление опубликованного сайта этим CLI не выполняется.

## Приватная накопленная память

Обычный живой запуск автоматически читает и дополняет `research/token-memory.json` вместе с публичными начальными примерами. Сохраняются текущий токен, найденные подтверждённые запуски и наблюдавшиеся funding/ранние участники; связь владельцев не подтверждается автоматически. Реальные снимки X и графика можно импортировать из базы браузера. Неизвестные поля не восстанавливаются из догадок.

`node memory-cli.mjs lookup CA` показывает сохранённую карточку и совпадения; `node memory-cli.mjs remember PRIVATE_CASE_OR_BACKUP.json` объединяет наблюдения. Рабочая база игнорируется git и не включается в ZIP. `--memory=BACKUP.json` задаёт отдельный входной набор; `--no-remember` отключает запись результата. Архивные replay-запуски не читают приватную память по умолчанию и не записывают фикстуры в неё.
