# DevLens

Сайт и расширение Chrome/Edge для исследования дев-кошельков Solana. Бесплатный адрес: **https://sokolov432.github.io/upscale_bot/**.

Ввод: CA либо ссылка Pump.fun/Solscan. Результат: creator, другие создания того же адреса, цепочки пополнения SOL/USDC/USDT, токены адресов в этих цепочках, миграции по реестру и ссылки на доказательства. Второй CA можно указать для сравнения. Идентичность владельцев разных адресов не объявляется установленной.

## Лупа на Axiom → выбранный чат ChatGPT

В версии 1.4 лупа возле названия токена на странице `axiom.trade/meme/…` отправляет фиксированный запрос поиска предыдущего запуска в **выбранный существующий разговор ChatGPT**, а финальный текст возвращается в боковую карточку Axiom и окно расширения. Это автоматизация открытой вкладки, а не подключение к внутреннему API ChatGPT. Она не создаёт доступ к инструментам, интернету или секретам, которых нет в выбранном чате. Для продолжения этой переписки выберите именно её вкладку.

1. Скачайте [ZIP 1.4](https://sokolov432.github.io/upscale_bot/devlens-extension.zip), распакуйте и установите через `chrome://extensions` → режим разработчика → «Загрузить распакованное расширение». При обновлении замените файлы в прежней папке и нажмите «Обновить».
2. Обновите вкладки Axiom и ChatGPT после установки. Откройте нужный разговор на **chatgpt.com/c/…** (также поддержаны разговоры внутри проектов `/g/…/c/…`). Откройте значок DevLens в панели браузера → **«Использовать этот чат»**.
3. Вернитесь в Axiom, откройте токен и нажмите лупу. Если сайт изменил разметку или новый пул ещё не попал в Dexscreener, вставьте полный CA в окно расширения → «Отправить в выбранный чат».
4. Оставьте браузер и вкладку чата открытыми. Дождитесь финального ответа: он появится в карточке Axiom и в расширении. Переключаться между вкладками можно. Повторное нажатие во время проверки того же CA не отправляет дубликат.

Для этого режима **не нужен API-ключ**. Нужна активная сессия ChatGPT и доступная модель; ограничения выбранного аккаунта остаются в силе. В другой чат запрос не перенаправляется. Черновик пользователя не перезаписывается; если чат занят или поле ввода недоступно, показывается ошибка. Закрытие/обновление вкладки прерывает связь; запрос мог уже попасть в чат, поэтому повтор запускается только нажатием пользователя. Через 20 минут без завершения проверка помечается ошибкой.

Из Axiom передаются только CA и название, а в чат — CA с фиксированным заданием поиска. Баланс, позиции, cookies и торговые действия не считываются. В расширении локально хранятся адрес выбранного разговора и последние 20 запросов/ответов. Текст отображается без выполнения HTML. Страница Axiom может прочитать показанный на ней ответ. Новых разрешений на торговый кошелёк нет.

Скрипт извлекает CA из явной ссылки токена рядом с заголовком. Адрес `/meme/…` трактуется как пул: при отсутствии явного CA запрашивается его base token через публичный Dexscreener; адрес пула не выдаётся за CA. Автоматическая вставка зависит от разметки Axiom и ChatGPT. Браузерная проверка выполняется на явно заданных макетах этих страниц: отправка в реальный пользовательский чат и разметка авторизованного Axiom в этой среде **не проверены**.

## Использование сайта

1. Откройте сайт. Сохранённые примеры NNN, ARC, CHUDBOB и BREACH доступны сразу; они явно помечены датой проверки.
2. Для нового CA скачайте ZIP версии **1.4.0** по кнопке «Расширение», распакуйте его.
3. Откройте `chrome://extensions`, включите режим разработчика, нажмите «Загрузить распакованное расширение» и выберите папку с `manifest.json`.
4. Обновите сайт: появится «Расширение подключено · 1.4.0». Вставьте CA и нажмите «Найти связи».
5. При необходимости нажмите **RPC**: сохраните свой HTTPS RPC в настройках расширения и нажмите «Проверить соединение». Проверка читает mainnet genesis, историю Pump.fun и реальную архивную транзакцию. Для Helius вставьте полный URL из личного кабинета; на публичном сайте ключ вводить не нужно.

Если была установлена более старая версия, замените файлы в её папке файлами из нового ZIP, нажмите «Обновить» в `chrome://extensions` и перезагрузите сайт. Страница требует версию 1.4.0: эта версия добавляет лупу на Axiom, отправку в выбранный чат и возврат ответа.

GitHub Pages — статический хостинг. Живые запросы идут из расширения к публичным API, поскольку Pump.fun не разрешает запросы с произвольного веб-origin. Это **не** постоянно работающий платный сервер. Пока вкладка закрыта, анализ не выполняется. Установка в режиме разработчика бесплатна; публикация в Chrome Web Store не выполнялась.

## Память расследований и скорость

База сохраняется в IndexedDB этого браузера: каждый CA, creator, выбранные пополнения, ранние покупатели с транзакциями, сайты/изображения, заметки, группы, решения о связях и снимки профилей. При повторном вводе сохранённого CA сетевых запросов нет. Начальные восемь записей содержат реальные изученные примеры, включая подтверждённую пользователем группу GLASS / SH. Новые пользовательские записи и заметки не загружаются в публичный репозиторий.

По умолчанию незнакомый CA получает ограниченную быструю проверку: до 24 запросов, не более пяти стартов запросов за скользящую секунду на источник. Читаются creator, транзакция создания, следующие четыре транзакции в том же блоке и выборка пополнений. Ранними покупателями считаются подписанты с положительным приходом именно исследуемого токена. Совпадают также порядок и пары подписей. Если окна в четыре транзакции недостаточно, покрытие помечается неполным. Глубокая проверка запускается отдельно. Поддержана проверка аккаунта Raydium LaunchLab в дополнение к Pump.fun. Если creator не удалось получить, предпринята отдельная проверка создания mint в пределах двух страниц истории. В таком режиме группа ранних покупателей может быть найдена, но плательщик транзакции не объявляется creator.

Сопоставление использует индекс по creator, ранним кошелькам, фандерам, доменам, профилям, изображениям, био и отпечаткам оформления. Частые участники и общие сервисы не становятся доказательством одного владельца. Один фандер, похожие био, изображение или число подписчиков — слабые признаки. Числа ранжирования не выводятся как процент уверенности. Подтверждения и отклонения сохраняются, могут быть сброшены и не перезаписываются примерами при обновлении.

Цель повторного поиска — до двух секунд. В локальной проверке интерфейса сохранённый GLASS открылся примерно за 70 мс без запросов; на живом RPC получение нового профиля заняло 1,6–2,6 секунды, а индексное сравнение — менее 2 мс. Это измерения, не гарантия задержки внешних API. Большая история или недоступный источник потребуют больше времени.

Снимки соцсетей сохраняются с датой и источником; в карточке показываются последние 20, история входит в резервную копию. В текущей версии био/подписчики вводятся пользователем; их автоматическое чтение из X не подключено. Неизвестные значения не превращаются в нули. Загруженное изображение сравнивается по 64-битному отпечатку; исходный файл изображения не сохраняется. Совпадение оформления само по себе не подтверждает владельца.

«Скачать резервную копию» сохраняет записи, снимки, заметки, решения и ИИ-сводки в JSON. Импорт проверяется до записи и объединяет базу атомарно. Полные исходные отчёты экспортируются отдельно кнопкой JSON в результате анализа. База относится к одному браузеру и origin сайта; очистка данных сайта удалит её. Для переноса на другое устройство используйте резервную копию.

## Необязательная ИИ-сводка

Кнопка «Объяснить совпадения с ИИ» обращается к OpenAI Responses API через расширение. В настройках расширения можно сохранить свой API-ключ и выбрать модель (по умолчанию `gpt-4.1-mini`; модель должна быть доступна вашему API-аккаунту). Разрешение запрашивается только на `https://api.openai.com/`. Оплата API отдельна от подписки ChatGPT. Ключ не отправляется странице, не записывается в базу и не включается в резервную копию. Без настройки ИИ быстрый поиск и память полностью работают.

Запрос выполняется только по нажатию кнопки: передаются текущие факты и до трёх лучших совпадений, включая сохранённые описания профилей и заметки. У API установлен `store: false`; результат сохраняется локально как ИИ-гипотеза. Модель не получает доступ к кошельку или инструментам. Внешние тексты считаются данными, не инструкциями. Неизвестные CA и выдуманные ID доказательств отклоняются. ИИ не меняет решения о связях автоматически. Успешная работа реального модельного аккаунта требует пользовательского ключа; проверки интеграции используют сетевые фикстуры и не расходуют API-токены.

## Локально, без расширения

Нужен Node.js 20+ (Node 24 для `--use-env-proxy`). Нет зависимостей npm.

```bash
cd devlens
node build.mjs
node server.mjs
# http://127.0.0.1:4318
```

В managed cloud используйте `node --use-env-proxy server.mjs`, сохраняя унаследованные proxy/CA переменные. Сервер слушает только localhost; для публичного backend потребуются отдельные настройки доступа и ограничения ресурсов.

CLI:

```bash
node cli.mjs TOKEN_CA --compare=PREVIOUS_CA --deep
```

CLI сохраняет публичные ответы в локальном `research/cache`. `--fresh` игнорирует кэш. Без `--fresh` сохранённые примеры — архив проверки, а не свежая котировка.

## Что проверяется

Новый автоматический сценарий поиска предыдущих запусков: [README_INVESTIGATOR.md](README_INVESTIGATOR.md). Запуск: `npm run investigate -- CA`; калибровка на разобранных примерах: `npm run calibrate`. Скрипт сохраняет доказательства и готовый `.run.mjs`, отдельно исключает привязанные активы и при наличии API-ключа использует ИИ для выбора следующих проверок.

- Реестр Pump.fun `coins-v2/{mint}` и `coins-v2/user-created-coins/{creator}` с пагинацией (источник ограничивает выдачу после offset 200).
- Подписанные/успешные транзакции через Solana RPC. Failed-транзакции исключаются.
- Если реестр Pump.fun недоступен, создатель читается из проверенного PDA BondingCurve: проверяются адрес, владелец программы, discriminator и поле creator по публичному IDL. Имя/символ берутся из Token-2022 metadata или проверенного Metaplex-аккаунта. Никакие внешние metadata URI автоматически не загружаются.
- В этом режиме создания восстанавливаются из CreateEvent в декодированных транзакциях адреса. Это выборка, а не полный список. Время запуска берётся из транзакции создания; если оно не найдено, обычные поступления не объявляются пополнениями до запуска. Статус миграции без отдельного подтверждения остаётся «Нет данных»; complete в кривой не объявляется состоявшейся миграцией.
- `CreateEvent` в логе программы Pump и Anchor event-CPI. Registry creator сверяется с creator события, если транзакция создания попала в проверяемую выборку.
- Пополнения SOL/USDC/USDT до исследуемого запуска; переводы в известных swap-транзакциях не объявляются обычными фандерами.
- Повторные отправители, одинаковые серии переводов, общие получатели вывода; пыль ниже 0,001 SOL / 1 USDC/USDT исключается.
- Ограниченный поиск вверх по переводам: обычный режим до 10 адресов / 2 звеньев; глубокий — до 24 адресов / 10 звеньев. До 2 000 сигнатур на адрес, 32/64 выбранных транзакций на промежуточный адрес и 64/128 на исходного дева; суммарный бюджет 240/640 транзакций. При сравнении двух CA бюджет делится между цепочками. Приоритет — время запуска и начало истории; это не полный архив всех транзакций.
- Дополнительно проверяются предыдущие создания 6/12 наблюдаемых контрагентов: совместных подписантов, получателей вывода, соседних получателей от нераспознанного как общий узел фандера. Это кандидаты по реестру; их история отдельно не считается прочитанной. Известные биржевые и слишком широкие узлы не раскрываются в соседних клиентов.
- В таблице сначала идут тот же creator, совпадения названия/символа и короткие связи. Совпадение имени не устанавливает владельца.
- Высокочастотный общий узел (не менее 1 000 сигнатур за сутки в выборке) не раскрывается как группа одного владельца. Реальные биржевые метки можно передать в `new Analyzer({labels: {ADDRESS: {exchange: true, name: '...', source: 'https://...'}}})`; встроенных выдуманных меток нет.

## Ограничения и выводы

**Перевод не доказывает общего владельца.** Биржи и сервисы обслуживают многих клиентов. Внутренний перевод между счетами CEX не виден в публичном блокчейне, поэтому гарантированно пройти такой разрыв нельзя. Совпадение времени/суммы — гипотеза, не идентификация человека. Два CA из поля сравнения не становятся «связанными» только от того, что их ввели вместе.

Массовые серии переводов сохраняются как доказательства движения средств с отметкой неоднозначности; они не отбрасываются целиком, потому что могут быть многоступенчатой подготовкой кошельков. Дальнейший поиск ограничен бюджетом. Ошибки RPC, неполные страницы, недоступные транзакции и непройденная очередь показаны в отчёте. Нулевой результат — отсутствие найденной связи в этой выборке, а не доказательство отсутствия связи вообще.

Расширение не подписывает транзакции, не читает cookie и не имеет разрешения `tabs`; `activeTab` и разрешение на chatgpt.com используются для выбора нужного чата; разрешение `offscreen` нужно для долгой проверки в worker без тайм-аута MV3. Host permissions: Pump.fun API, PublicNode и публичный Solana RPC. Метод `getAccountInfo` используется для чтения аккаунтов программы и метаданных. Для своего RPC запрашивается отдельное разрешение только на выбранный HTTPS-origin. Сетевой мост карты работает только на странице этого проекта и localhost:4318; сайт может запрашивать только анализ валидного CA, не произвольный fetch. Отдельные content scripts работают на Axiom и chatgpt.com для явно выбранного чата. Для определения mint по пулу разрешён публичный api.dexscreener.com. История и CA — публичные on-chain данные; они передаются источникам для поиска. Подключение торгового кошелька и приватные ключи не нужны. Необязательный URL своего RPC хранится только в `chrome.storage.local` расширения: он не передаётся странице, не записывается в отчёт и не входит в ZIP. При HTTP 403/недоступном архиве проверяется независимый публичный провайдер; при 429 выдерживается пауза, а ротация ради обхода лимита не выполняется.

Ошибка чтения истории исходного дева или ноль декодированных транзакций прерывают анализ с ошибкой доступа; наличие токена в реестре не превращает её в успешный пустой результат. Счётчики показывают фактически прочитанные транзакции/адреса и достигнутую глубину, отдельно от заданного лимита.

Архив CHUDBOB воспроизводит реальную проверку: 197 транзакций у 7 адресов, 99 записей токенов с исходным CA. Среди кандидатов — два более ранних CHUDBOB по цепочке пополнения. Это не 98 доказанных запусков одного человека; границы выборки и источники перечислены в архиве. Ключ RPC в архив не включён.

Архив BREACH воспроизводит пользовательский сценарий: реестр локально отвечает HTTP 403, а 13 транзакций, creator и событие запуска прочитаны из настоящего mainnet через RPC. Имитация касается только отказа реестра и явно отмечена в snapshotNote. Он не содержит выдуманных переводов или созданий.

Layout программы: https://github.com/pump-fun/pump-public-docs/blob/main/idl/pump.json. Raydium LaunchLab: https://github.com/raydium-io/raydium-sdk-V2/tree/master/src/raydium/launchpad.

## Проверка и публикация

```bash
node --test test/*.test.mjs
node build.mjs
```

Браузерные проверки (Playwright с полным Chromium): `python test/browser_smoke.py`, `python test/browser_memory.py` и `python test/browser_chat.py`. Они проверяют реальный мост расширения с явно заданными ответами источников, IndexedDB, сохранение между перезагрузками, отмену решений, импорт/экспорт, ИИ-сводку и отсутствие ключа в базе. Запуски не обращаются к платному модельному API.

Готовые файлы — `docs/`, расширение — `docs/devlens-extension.zip`. GitHub Pages публикует ветку `gh-pages`, корень `/`. Исходники и подготовленный `docs/` находятся в `codex/devlens`. Для обновления пересоберите сайт и отправьте изменения этой ветки: workflow `Publish DevLens` обновит `gh-pages` и запросит сборку Pages. Платный домен не нужен. Начальная публикация выполнена стандартной веткой `gh-pages`; создание сайта через административный API было недоступно текущему подключению. GitHub Actions также проверяет тесты и совпадение сборки с исходниками.
